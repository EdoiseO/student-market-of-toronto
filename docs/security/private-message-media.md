# Private attachment delivery

Private attachments use `/api/message-media/<attachment UUID>`. Every GET, HEAD and range request validates the signed-in viewer, queries the exact attachment with that viewer's RLS credentials, and only then resolves and downloads its physical object with a server-only service client. Current moderation authority comes from the database. A URL is an identifier, not a transferable bearer capability. Participants retain the existing policy for their own conversation history; unrelated staff and demoted moderators do not inherit that access.

The route emits private/no-store browser and CDN headers on success and failure, does not redirect to Storage, does not emit reusable validators or 304 responses, and does not put privileged fetches in the Next fetch cache. Images and videos keep their MIME types; single byte ranges support seeking. Multi-ranges and invalid ranges receive 416. If-Range cannot match an absent validator, so it receives a newly authorized full response. Upstream reads stop at the attachment's validated size, capped at the existing 10 MiB limit, and fail closed on inconsistent data.

Initial conversation pages, older history, incoming Realtime messages, completed sends and moderation detail all use this route. Completed sends hydrate actual committed attachment IDs; a failed display refresh does not retry the committed message. Public listing photos continue to use the shared gallery and image optimizer. Private thumbnails and fullscreen images bypass optimization. Next's optimizer permits only the existing local public assets and public remote sources; it rejects the new private route and legacy signed Storage URLs before its local cache lookup.

New uploads use the existing reservation and idempotent send flow, with raw bytes and explicit no-store upload headers. Database upload, immutable-object, deletion and account-retirement guards remain enforced. Account cleanup requires the media-location RPC and includes both copies of any interrupted legacy relocation; an unavailable RPC fails cleanup rather than silently skipping private objects.

## Rollout and evidence

The corresponding database migration must precede this application version. Existing attachment paths stay logical identifiers; the service-only resolver selects a verified relocated copy when present. Legacy keys require a separate, bounded relocation with byte hashes, activation, deletion through Storage, and exact old-URL replay checks. Do not infer that new headers or a new deployment revoked already issued URLs, CDN entries, browser copies or old deployment aliases.

The regression suite `node --test tests/private-message-media.test.mjs` exercises exact-URL permission loss, HEAD/ranges, conditional requests, unauthorized and unavailable services, unsafe metadata, bounded upstream bodies, and the installed Next optimizer's allowlist. Native database tests and hosted requests are separate requirements. A passing unit suite alone is not proof of CDN invalidation. Preserve the original failing hosted receipt and capture new hosted evidence after relocation and platform-cache retirement.

Already downloaded bytes cannot be recalled. The guarantee begins with authorization for each new request after a committed authority change; a request authorized before demotion may finish. No database lock is held across the Storage network request. Required GitHub approval, hosted HTTPS recovery checks and browser/device validation remain independent demo release gates. Custom SMTP and general student-inbox delivery are deliberately deferred until before real student onboarding.
